# 双地财报附注的含义核对与定稿

跨地披露用稿采用 UTF-8 编码，人物、单位和记录均为合成内容。

| 资料 | 字段 |
| --- | --- |
| `资料/正文.json` | `id`、`market`、`entity`、`period`、`language`、`text` |
| `资料/表行.json` | `id`、`market`、`table`、`period`、`entity`、`amount`、`unit`、`footnote` |
| `资料/脚注与通告.json` | `id`、`market`、`notice`、`text` |

每份资料是 JSON 数组。记录中的字段值按来源原样保留为字符串，逗号和顿号可以属于字段内容。资料中可能有转述、不同的拼写以及较晚录入的更正。数字及日期在这些文件中沿用各资料自身的含义；原文位置以记录编号及文本范围定位。

Node.js 22 环境下运行以下命令可安装锁定的项目环境、检查素材格式并读取各类资料的数量。

```sh
npm ci --offline --ignore-scripts --no-audit --no-fund
npm test
npm run materials
```

`readMaterials` 只读取资料，不解析其中的正文含义。

## 比对工作台

`workbench.js` 在 `readMaterials` 之上做含义核对与定稿辅助：

```sh
node workbench.js                          # 读取 资料/，向标准输出打印比对报告
node workbench.js --out 输出               # 另把审计轨迹写入 输出/审计轨迹.json
node workbench.js --approvals 批准.json    # 读入财务批准、附适用条件的换算说明
node workbench.js --json                   # 直接输出机读审计轨迹
```

报告与审计轨迹覆盖：

- **陈述分类**：每条正文按本期事实 / 以前期间重列 / 政策说明 / 未来计划归类，并提取金额的期间、报表主体、单位与方向；期间词按所在句判定，跨段、跨表的附注按主张及其条件对应到表行。
- **比对决定**：同地正文与表行先按主张及金额互认成组，再跨地比较，给出共同引用 / 按各地口径发布 / 不可对照 / 暂缓的结论。术语相同（如“确认 / recognize”）但确认时点或政策基础不同的，标为不可对照且不阻断本地发布。
- **更正与重列**：更正通告落位到具体表行；未受影响的原稿可按本地口径发布，共同摘要引用被取代行前须重审，且不得把当前说明与重列前数字拼接。
- **脚注适用范围**：共享脚注按分句条件落到各行；适用范围被更正改变后逐行重核，任一已签署行不能为整页兜底。
- **缺口**：单位未定义、主题未指明、更正未落表、换算说明缺失、政策条件缺失、译文或转述缺对侧支持等，逐条定位供人工确认。
- **摘要校验**：共同摘要选取内容须属同一期间、同一合并范围；跨币种数值复用须财务批准的换算说明且覆盖同一合并范围。
- **审计轨迹**：每项决定附证据（资料名、记录编号、文本范围）、语义差异与未发布比较数值的原因，供审阅人回查。

换算说明批准文件示例：

```json
{
  "conversions": [
    { "fromCurrency": "local", "toCurrency": "元", "rate": 1, "scope": "合并", "conditions": "仅2026年度合并口径", "approvedBy": "财务组" }
  ]
}
```
